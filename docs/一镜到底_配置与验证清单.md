## 为什么不选 Tier2（暖启动）

1. **会废掉潜空间根治**：根治（跨段 latent 视频续写）只在 `多段无缝 + 标准真骨架` 下触发；选 Tier2 即退回像素 prefix 末帧冻结。
2. **实测画质更弱**：此前对照测试，Tier2 在 4 步蒸馏管线下模仿力 + 画质均弱于多段无缝。
3. **你已确认**：本次选择「多段无缝 + 标准真骨架（推荐）」，与另三项完全兼容。

## 代码级链路核对（已逐项确认无死路）

- **多段而非单遍**：`single_pass` 仅在 `strategy == CONTINUITY_SINGLE_PASS` 时为真（planner.py:152）。你选多段无缝 → `single_pass=False` → 多段 + 重叠 32（SCAIL-2 锁），潜空间拼接有段可拼。
- **根治触发**：runner.py:382-391 对 `标准 SCAIL 真骨架` 且 `seg>0` 同时置 `prev_video_path`（标准 SCAIL 重编码路径）与 `prev_latent_path`（WanAnimatePlus 加载路径），并 `latent_warmstart=True`。
- **无像素 prefix 误触发**：animateplus.py:300-303 用 `if latent_warmstart … elif prev_video_path …` 守卫，标准真骨架走 `if` 分支，不会落到 `elif` 的像素 prefix 冻结；且 runner 每段后（441/442-443）更新两个路径，上段 latent 必已落盘。
- **落盘 + 解码**：runner 每段取 `latent_path`（429）；stitcher 对 `STITCH_LATENT_BLEND` 走 `_stitch_videos_latent`（stitcher.py:247-250）→ 合并 `merged.pt`（508）→ `_decode_latent_via_comfyui`（已含 VHS.images 重连修复）→ 输出。

## GPU 本机实跑验证清单

启动执行后，日志应出现以下三处签名，才算 根治 + 潜空间 全链路生效：

1. **根治已注入**（二选一，取决于模板家族）
   - 标准 SCAIL：`SCAILAdapter … latent 暖启动注入: prev=… → VHS(…)+Encode(…) → Sampler.samples(+noise)`
   - WanAnimatePlus：`AnimatePlusAdapter … latent 暖启动注入(根治): … → YunjiiLoadLatent(…) → SamplerSettings.samples(+noise)`
2. **宽重叠混合**：stitcher 日志 `latent 重叠淡化 N 帧(像素重叠O)` 中 **O=32, N=8**（对齐猴子工作流 8 latent 帧自然连贯方案）。
3. **潜空间解码成功**：`✨ 潜空间拼接解码完成`。

### 缺失时的排查

- **缺 ①**：确认「生成质量模式」确实是「标准 SCAIL 真骨架（推荐）」、且「连贯策略」= 多段无缝（非暖启动/单遍）；并确认不是 single_pass（planner 单遍连贯模式 未勾选）。
- **缺 ③**：检查每段 latent 是否落盘 `output/yunjii_v2v/{run_id}/seg_*_latent.pt`；缺失则根治静默跳过 → 潜空间拼接回退像素拼接。

## 已知限制 / 风险

- 沙箱无 GPU，全部执行验证依赖本机（RTX 3090 / sm_86）。
- fp8 在 3090 无 FP8 硬件走软件回退，建议启动前设 `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:False` 规避 `CUDA error 214` 竞态。
- 启动器「启动超时」看门狗可能误杀（~60s 阈值 vs 全量加载 ~80–95s）；若被误杀，进程以 Code 0 干净退出**非崩溃**，可手动启动绕开看门狗或调大超时阈值。
