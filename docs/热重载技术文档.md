# 云集智能插件 - 热重载技术文档

## 概述

热重载（Hot Reload）允许在 ComfyUI 运行期间重新加载插件 Python 模块，无需重启整个 ComfyUI 进程。这大幅缩短了开发调试周期——从修改代码到验证结果，仅需2-3秒。

## 背景

ComfyUI 的自定义节点在启动时一次性加载，之后不会自动重新读取磁盘上的代码变更。传统开发流程为：

```
修改代码 → 重启 ComfyUI（30-60秒）→ 等待模型加载 → 测试 → 发现问题 → 重复
```

热重载将此流程缩短为：

```
修改代码 → 点击热重载（2秒）→ 测试 → 发现问题 → 重复
```

## 架构设计

### 核心原理

ComfyUI 的节点注册机制分为两层：

1. **插件层**：每个插件的 `NODE_CLASS_MAPPINGS` 字典，定义在插件的 `__init__.py` 中
2. **ComfyUI 全局层**：`nodes.py` 中的全局 `NODE_CLASS_MAPPINGS` 字典，ComfyUI 执行工作流时从这里查找节点类

启动时，ComfyUI 调用 `load_custom_node()` 读取插件的 `NODE_CLASS_MAPPINGS`，将其合并到全局注册表。之后插件模块的修改不会自动反映到全局注册表。

### 热重载流程

```
┌─────────────────────────────────────────────────┐
│  用户触发热重载（前端按钮 / API / BAT）           │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│  Step 1: 清除模块缓存                           │
│  从 sys.modules 中删除所有 yunjii 相关模块       │
│  包括:                                           │
│    - comfyui-video-frame-yunjii                  │
│    - comfyui-video-frame-yunjii.nodes            │
│    - comfyui-video-frame-yunjii.engine.*         │
│    - comfyui-video-frame-yunjii.engine.adapters.* │
│    - comfyui-video-frame-yunjii.engine.effects.* │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│  Step 2: 重新导入插件                           │
│  importlib.import_module() 从磁盘重新加载        │
│  所有 Python 源文件被重新解析和执行              │
│  新的 NODE_CLASS_MAPPINGS 生成                   │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│  Step 3: 刷新 ComfyUI 全局注册表                │
│  将新的节点类写入 nodes.NODE_CLASS_MAPPINGS      │
│  将新的显示名写入 nodes.NODE_DISPLAY_NAME_MAPPINGS│
│  ComfyUI 后续执行工作流时使用更新后的节点类      │
└──────────────────────┬──────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────┐
│  返回重载结果                                    │
│  {                                              │
│    "status": "ok",                              │
│    "reloaded_modules": 10,                      │
│    "node_count": 8,                             │
│    "nodes": ["MotionAnalysisNode", ...],        │
│    "errors": []                                 │
  }                                              │
└─────────────────────────────────────────────────┘
```

### 关键代码

热重载的核心实现在 `__init__.py` 中：

```python
def _clear_module_cache():
    """Step 1: 从 sys.modules 中删除所有插件模块"""
    cleared = []
    for mod_name in list(sys.modules.keys()):
        if mod_name == _PLUGIN_PACKAGE or mod_name.startswith(_PLUGIN_PACKAGE + "."):
            del sys.modules[mod_name]
            cleared.append(mod_name)
    return cleared

def _reload_plugin():
    """Step 2+3: 重新导入并刷新全局注册表"""
    errors = []
    cleared = _clear_module_cache()

    # 重新导入插件（从磁盘读取最新代码）
    plugin_mod = importlib.import_module(_PLUGIN_PACKAGE)
    new_mappings = getattr(plugin_mod, "NODE_CLASS_MAPPINGS", {})
    new_display = getattr(plugin_mod, "NODE_DISPLAY_NAME_MAPPINGS", {})

    # 刷新 ComfyUI 全局节点注册表
    import nodes as comfy_nodes
    for name, node_cls in new_mappings.items():
        comfy_nodes.NODE_CLASS_MAPPINGS[name] = node_cls
    comfy_nodes.NODE_DISPLAY_NAME_MAPPINGS.update(new_display)

    return {"status": "ok", "reloaded_modules": len(cleared), "node_count": len(new_mappings)}
```

## 使用方式

### 方式一：前端工具栏（推荐）

ComfyUI 页面右下角显示 `Yunjii 🔄热重载 📋日志` 工具栏：

- **🔄 热重载**：点击后显示重载结果（如 `✅ 10模块, 8节点`）
- **📋 日志**：打开日志查看面板，查看节点执行详情

### 方式二：API 调用

```bash
# 热重载
curl -X POST http://127.0.0.1:8188/yunjii/reload

# 查看插件状态
curl http://127.0.0.1:8188/yunjii/status

# 查看日志列表
curl http://127.0.0.1:8188/yunjii/logs

# 查看指定日志最后50行
curl "http://127.0.0.1:8188/yunjii/logs?file=yunjii_20260526_072738.log&tail=50"
```

### 方式三：BAT 脚本

双击 `reload.bat`，自动执行热重载并显示状态和最新日志。

## 适用范围

### ✅ 热重载能生效的改动

| 改动类型 | 示例 | 说明 |
|----------|------|------|
| 节点内部逻辑 | 修改 `analyze()`、`plan()`、`run()` 方法体 | 最常见场景 |
| 算法参数 | 修改阈值、权重、默认值 | 如灵敏度、帧数限制 |
| 提示词模板 | 修改负面提示词、质量增强词 | MimicPromptGenerator |
| 适配器逻辑 | 修改 `ComfyUIAdapter` 的工作流修改逻辑 | Runner 节点 |
| 效果模块 | 修改 `mimic.py` 等效果模块 | 模仿/创意/运镜 |
| 调试日志 | 修改 `debug_log.py` | 日志格式和内容 |
| 数据类型 | 修改 `types.py` 中的数据结构 | SegmentInfo 等 |
| 工具函数 | 修改辅助函数 | 场景检测、帧提取等 |

### ❌ 热重载无法生效的改动

| 改动类型 | 原因 | 解决方案 |
|----------|------|----------|
| 新增/删除节点 | ComfyUI 前端节点列表在启动时固定 | 重启 ComfyUI |
| 修改 `INPUT_TYPES` | 前端 Widget 在节点创建时渲染 | 重启 ComfyUI + 刷新浏览器 |
| 修改 `RETURN_TYPES` / `RETURN_NAMES` | 连线类型检查在启动时完成 | 重启 ComfyUI |
| 修改前端 JS | 浏览器已缓存旧 JS 文件 | 刷新浏览器（Ctrl+Shift+R） |
| 修改 `__init__.py` 路由 | API 路由在启动时注册 | 重启 ComfyUI |

## 技术限制

### 1. 模块状态丢失

热重载会清除所有模块的 `sys.modules` 缓存，这意味着：
- 模块级全局变量会重置为初始值
- 已加载的模型不会重新加载（模型由 ComfyUI 管理，不受影响）
- 日志文件的 `_current_log_file` 会重置，下次写日志时自动创建新文件

### 2. 已创建节点实例

ComfyUI 画布上已存在的节点实例不会自动更新。热重载后：
- **新执行的工作流**：使用更新后的节点类
- **已执行但缓存的结果**：不会自动重新计算（需要修改输入触发重新执行）

### 3. 并发安全

热重载期间如果有工作流正在执行，可能出现短暂的不一致。建议：
- 在工作流执行完成后触发热重载
- 或先中断当前执行，热重载后再重新执行

### 4. 循环导入

如果模块间存在循环导入，热重载可能失败。当前代码结构已避免循环导入：
- `nodes.py` → `engine.debug_log`（单向依赖）
- `engine/planner.py` → `engine.types`, `engine.debug_log`（单向依赖）
- `engine/runner.py` → `engine.adapters`, `engine.types`, `engine.debug_log`（单向依赖）

## 调试日志系统

热重载配合调试日志系统，形成完整的开发调试闭环。

### 日志文件

- **位置**：`ComfyUI/output/yunjii_logs/yunjii_YYYYMMDD_HHMMSS.log`
- **命名**：每次 ComfyUI 启动后首次执行节点时创建，带时间戳
- **编码**：UTF-8

### 日志级别

| 级别 | 用途 | 颜色（前端面板） |
|------|------|------------------|
| DEBUG | 详细参数、数据流 | 灰色 |
| INFO | 节点开始/完成、关键结果 | 蓝色 |
| WARNING | 非致命问题 | 橙色 |
| ERROR | 执行失败 | 红色 |

### 日志格式

```
[2026-05-26 15:30:45.123] [INFO] [MotionAnalysis] ===== 节点开始执行 =====
[2026-05-26 15:30:45.124] [DEBUG] [MotionAnalysis]   参数 视频文件 = test.mp4
[2026-05-26 15:30:45.125] [DEBUG] [MotionAnalysis]   参数 灵敏度 = 0.3
[2026-05-26 15:30:46.500] [INFO] [MotionAnalysis] 视频信息: 240帧, 30.0fps, 8.0秒
[2026-05-26 15:30:46.800] [INFO] [MotionAnalysis] 分析完成: 3段, 3关键帧
[2026-05-26 15:30:46.801] [INFO] [MotionAnalysis] ===== 节点执行完成 ===== 3段, 3关键帧
```

### 便捷函数

| 函数 | 用途 |
|------|------|
| `node_start(tag, **params)` | 记录节点开始执行及参数 |
| `node_end(tag, summary)` | 记录节点执行完成 |
| `node_error(tag, msg)` | 记录节点执行失败 |
| `debug/info/warn/error(tag, msg, *args)` | 通用日志 |
| `data_flow(from, out, to, inp, type, preview)` | 记录数据流 |
| `separator(title)` | 插入分隔线 |

## API 端点

| 端点 | 方法 | 功能 | 参数 |
|------|------|------|------|
| `/yunjii/reload` | POST | 热重载插件 | 无 |
| `/yunjii/status` | GET | 查看插件状态 | 无 |
| `/yunjii/logs` | GET | 列出日志文件 | 无 |
| `/yunjii/logs?file=X&tail=N` | GET | 查看指定日志 | `file`: 文件名, `tail`: 行数 |

## 典型开发工作流

```
1. 启动 ComfyUI（首次需要完整启动）
         │
2. 修改节点代码（如 nodes.py 中的算法逻辑）
         │
3. 触发热重载
   ├── 点击前端 🔄 按钮
   ├── 运行 reload.bat
   └── curl -X POST /yunjii/reload
         │
4. 在 ComfyUI 中执行工作流测试
         │
5. 查看 📋 日志面板确认执行结果
         │
6. 发现问题？回到步骤2
         │
7. 需要修改 INPUT_TYPES / 新增节点？
   → 重启 ComfyUI（仅此情况需要）
```
